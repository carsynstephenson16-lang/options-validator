## Work packages

### WP-A — `options_researcher/launchagent_state.py`

A.1 **Pure comparison.** `compare(*, tracked: Mapping[str, str], installed: Collection[str], loaded: Collection[str], disabled: Collection[str], prefix: str = OWN_PREFIX) -> tuple[LabelState, ...]`. `OWN_PREFIX = "com.carsyn.options-validator."` is a module constant (LLM-proposed literal matching every tracked options-validator label; R1-21). `tracked` maps label → tracked plist path (repo-relative); `installed` = labels whose file `~/Library/LaunchAgents/<label>.plist` exists (exact `*.plist` stem; the two `daily-ritual.plist.bak-*` files present on 2026-09-09 do not match the glob — Test-verified, R1-9); `loaded` = labels launchd reports in the gui domain; `disabled` = labels in `launchctl print-disabled` output marked `=> disabled` (R1-6). `LabelState` is a frozen dataclass `(label, tracked_path: str | None, installed: bool, loaded: bool, disabled: bool, state: State)`; `State` is a `StrEnum`, in sort order:
- `INSTALLED_NOT_LOADED` — tracked, installed, enabled, not loaded. **The incident class.**
- `DISABLED` — tracked, installed, `=> disabled` (indistinguishable from the above by `list` alone; the remedy differs — `launchctl enable` first, R1-6). Precedence over `LOADED`: `launchctl disable` takes effect at the next bootstrap, so a label can be both `=> disabled` and currently loaded; it reports `DISABLED` (R3-4).
- `LOADED_NOT_INSTALLED` — loaded, tracked, no installed file (launchd holds a job whose plist is gone — the inverse incident); C.1 maps it to `DEGRADED` (R3-4).
- `UNTRACKED` — loaded or installed under `prefix` with no tracked plist (today: none, given A.2's four roots; kept so a stray agent is visible).
- `NOT_INSTALLED` — tracked, no installed file (today: `job-health-digest`, `schwab-chain-intraday`; owner-gated, informational).
- `LOADED` — tracked, installed, loaded.
Every tracked label is compared regardless of prefix (so `com.carsyn.repo-reconcile` is covered — R1-18); `prefix` only bounds `UNTRACKED` discovery, which keeps `com.carsyn.pick-dashboard` (equity-research's agent, Test-verified) out. `compare()` classifies exactly the label universe `set(tracked) | {l for l in installed if l.startswith(prefix)} | {l for l in loaded if l.startswith(prefix)}`; `disabled` never contributes a label, and non-prefix `installed`/`loaded` labels never create a row (Test-verified 2026-09-09: `~/Library/LaunchAgents` holds thirty-seven `*.plist` files of which thirty-one are neither tracked nor prefixed, and `launchctl print-disabled gui/501` marks four `com.apple.*` labels `=> disabled`). The classifier is an ordered `if/elif` chain in the listed sort order; every label in that universe satisfies `tracked or (prefix and (installed or loaded))`, so the fourteen reachable `(tracked, installed, loaded, disabled)` tuples each map to exactly one state, and the two unreachable ones (`tracked=False, installed=False, loaded=False`) raise `ValueError` rather than falling through to a default. D.1 enumerates all sixteen combinations — asserting the fourteen states and the two raises — and asserts that a disabled-only label and a non-prefix installed label each produce no row (R3-4, R4-1). `installed` assumes the installed filename stem equals the plist's `Label` (Test-verified 2026-09-09: true for all twelve; a mismatched installed file would read as `NOT_INSTALLED` + `UNTRACKED` — R3-10). No I/O in this function.

Discovery walks those directories, not git, so it works in the ops checkout unattended (Test-verified by the round-2 reviewer: `~/options-validator-ops` at `645365b` holds the same twelve files).

A.3 **launchd adapter** — the ONLY place `subprocess` appears; every call takes an injectable `run=subprocess.run` so tests never spawn launchd.
